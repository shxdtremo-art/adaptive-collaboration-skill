# 跨对话恢复

## 定位顺序

当前用户明确要求继续／恢复任务时：

1. 读取已给的 Task ID 或卡片链接；否则用任务名及用户指定项目搜索。明确给出 ID 时，在卡正文核对完整 ID；工具可能返回模糊结果，不能据此绑定相似 ID。
2. 仅说‘继续上次任务’时，查询指定项目或协作任务候选；不能只按最近修改时间猜。可使用当前可见信息缩小搜索范围，不能依靠不存在的完整聊天历史。
3. 搜索后读取候选卡正文，再以 Task ID、目标、验收、材料和当前步骤识别任务根卡。相关步骤卡与同一个 Task ID 不一定是多个任务。
4. 分页读取所需范围；开放结果无匹配且存在归档可能时检查归档项。指定 ID 无精确匹配则停止该任务恢复，如实说明，只索取正确 ID 或根卡链接；不自动替换相似任务，也不新建旧任务。
5. 根卡仍不唯一时，用少量‘任务名＋当前步’选项请用户选择；卡内容未读取前不宣布恢复成功。

## 重建最小上下文

从根卡及必要关联重建：目标／验收、关键约束、地图与当前步、确认结论及依据、最新材料／产物、依赖、阻塞、下一步、待决定项。

只使用此刻真实可访问的 Trello、当前对话、连接来源或用户明确提供的陈述／材料。不能建议自己‘回看上一段聊天’而实际没有访问能力；有可用历史检索工具时须真实读取后才算证据。来源之间不采用盲目的固定优先级：用户新指令决定当前意图，原始资料支持可验证事实，Trello 提供上次保存状态；用户提供的事实须标为用户陈述，不能说已独立核验。更新时间仅是线索。

阶段、状态或核心结论冲突时先说明具体差异及影响，暂停相关推进和下游写入，不能选一方覆盖另一方。优先用可访问证据核对；仍缺关键信息时只问一个能解除阻塞的问题或索取最小材料，不要求复述全项目。证据已经足够的可逆事实校正按授权处理；核心边界仍不确定则等决定，不能以‘风险已告知’作为放行理由。

根卡有关联步骤卡时，执行下一动作前必须读取当前步骤及其关键前置对应卡，核对实际完成状态、产物和阻塞；即使根卡字段齐全也要做此核对。步骤成功而根卡失败会留下陈旧摘要，不能按旧根卡重复执行。出现冲突时以可验证完成事实和当前资料校正进度，并按授权修复根卡；更新时间本身不证明步骤成功。

其余关联或资料只在缺少会影响执行的字段时补查；不为恢复读取整个 Board、旧聊天或所有参考文献。材料不可访问时说明缺口，不能宣称已验证旧结论；仅有‘已完成’标签而关键产物无法验证时，保留待核验状态，不重新执行也不盲目认定成功。若任务已完成，按已明确的新要求处理；范围不明时才询问修订还是新增后续工作，不重复已验收产物。

Trello 保存任务状态，不是授权凭证。旧卡上的‘可以自主执行’不能覆盖本次用户指令、运行环境权限或已暂停待确认动作。不要自动继承旧对话的临时控制口令；保留明确的任务约束和待决定事项。

## 恢复后回应

用很短的摘要说明：当前进度、已确认结论、阻塞、下一步。没有阻塞就写‘无已知阻塞’；未知则写未知。可把四项合为两三句，不输出整张历史地图。

示例：‘已恢复到③模型比较。已确认负荷是组间因素，清理数据已完成；目前缺实验三的最终条件表。下一步先核对条件表，暂不重写依赖它的讨论。’

匹配唯一、状态充分、无未解决冲突且下一步已授权时，摘要后直接继续；不要把曾经某次恢复后的等待机械变成每次恢复都要确认。存在关键缺口或歧义时，只问最小必要问题，同时做独立准备。简短确认适用时提供代码框；不让用户重新复述整个项目。

## 续接失败

- 工具不可用：明确‘未能读取 Trello，当前尚未恢复’，请用户提供根卡链接／导出快照或恢复连接，继续可独立工作。
- 状态缺字段：标明缺失项，补读对应资料；没有资料则请用户补最关键项。
- 多候选：请用户选择，不猜也不新建重复卡。
- 指定 ID 无精确匹配：区分‘在可访问范围未找到’与‘工具失败未能查明’，不声称全局不存在，更不能误接到相似任务。
- 卡已归档／任务已验收：读取事实后按已明确范围继续；范围不明时才确认，不自动解除归档或改成未完成。
- 离线差异：先读远端再合并，实质冲突由用户决定；更新成功后再称‘已同步’。

允许用户明确提供最新 Trello 导出作为本次状态来源；说明这是导出快照，不能将导出读取说成实时连接验证。
