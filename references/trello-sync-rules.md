# Trello 同步规则

## 准备与范围

使用当前可用的 Trello 插件工具；先查看工具说明与实际参数，不假设所有环境都支持相同字段。只读必要任务范围，不把私人材料扩散到无关或公开项目。

开始持久管理时，先查用户已指定的 Board／卡片；没有指定则搜索任务名或 Task ID。多处均可能匹配时请用户选择一个目标，不能自选项目覆盖。需要新建但没有唯一可用目标时，只询问保存位置；不擅建公开 Board。

普通低风险新增、更新、移动和状态同步可在已确认范围内自主处理。根据实际后果识别删除、批量归档、大规模重构与不可逆修改，无需用户说出‘破坏性’。执行前先给具体对象、改动方案、信息损失与保留／恢复方式，并取得用户对此具体方案的明确确认；优先提出可逆替代，但批量归档仍需确认，不能用可逆名义绕过。

‘旧卡都删掉，按你觉得合理的重建’表达重构意图，不代表用户已确认尚未形成的新结构或丢弃范围。先完成只读调查和可审阅方案，再问一次必要确认；若同一具体方案已明确确认，不重复审批。保留 Task ID 和仍有效的信息，不扩大确认范围。技能规则不替代环境审批，工具拒绝时不能换途径绕过权限。

## 最小状态结构

默认每个长期任务一个可检索的**任务根卡**，卡名包含 `[Task ID] 任务名`；根卡保存当前权威快照。较小任务在根卡用 Checklist 即可，较大任务才增加关联步骤卡。Board 对应项目、List 可对应阶段或状态；不为形式完整重建现有 Board。

使用模板中的最小字段：稳定 Task ID、目标与验收、关键约束、地图及当前步、已确认决策与依据、材料与产物定位、阻塞、下一步、更新时间。依赖、分支、关联卡及明确期限按需增加。空字段删除或写‘无’，不要堆大量待填项。

Task ID 首次分配时搜索检测冲突；已有 ID 永不随标题或路线变化改写。`PSY-OTHER-CENTRICITY-001` 只是示例，不给所有任务重复使用。缺少原 ID 时标为待定位，不捏造为已经保存的身份。

根卡记录‘现在相信什么、依据是什么、做到哪、下一步’，不是聊天仓库。确认结论、工作假设、待验证和废弃结论分开；被新证据推翻的判断从当前结论移出，必要时留一行替代原因。

材料记录可再次访问的文件身份／版本或持久链接，必要的分析口径与执行产物。不能只写‘见上次聊天’、‘按之前代码’或临时 `/tmp` 路径。不要在描述中存凭据或整段敏感原始数据。

## 何时写

仅在以下语义事件有实际变化时同步：方向确认、地图建立、步骤开始或完成、关键决策、阻塞、重排、验收。同一次响应中的相邻事件合并为一次状态更新；没有实质变化则不写。临时想法、普通问答、已淘汰小分支和每轮聊天不写。

写入当前快照而非逐轮追加日志。关键理由只保留能解释下一步选择的摘要。明确截止时间才使用 due／Planner；不为了任务存在而添加日程。状态层不保存完整对话；对话中的临时‘这一步先问我’不自动变成跨对话永久权限。

同步服从协作协议的风险门槛及已确认阶段，不能按内容主题自行决定‘这属于后续阶段，所以写那里’。存在未解决的结构冲突时，不新增下游候选、决定或阶段状态；必要阻塞／QA 结果只记根卡或当前已确认阶段。普通无冲突的同步照常自主处理，不每次请示。

阶段完成须有对应验收依据并做阶段 QA；迁移后是否继续由用户当次授权决定，不一律暂停，也不超出‘只切换阶段’等限制。只更新必要承接内容与当前状态，不顺手重写后续全部阶段。假设场景、测试讨论或用户想收尾，不构成真实完成事实。

## 写入顺序与完整性

1. 读取目标卡正文及必要关联，取得真实卡、List、Board 标识；搜索结果和短链不直接作为写入 ID。
2. 写前核对未解决冲突与阶段边界，通过门槛后只合并本次确定变化；保留用户自写段落。已有卡用模板中的 `ADAPTIVE-COLLABORATION:BEGIN/END` 标记划定协作状态区块，只修改区块内内容。旧卡没有标记时先识别既有协作内容并迁移；无法可靠区分时追加独立区块，不能覆盖或删除用户内容。
3. 同一卡片的描述、移动、Checklist 更新按依赖顺序执行；若涉及步骤卡和根卡，先完成步骤事实再更新根卡摘要，不把部分成功写成全部成功。
4. 检查每个工具返回的成功状态。重排或多卡更新后读取有关对象核对；普通单卡更新以明确成功返回为准，不为每次同步增加无意义查询。
5. 记录成功对象与待重试差异；只在必要时报告‘已同步／部分待同步／未同步’。

更新描述是读改写操作。写前如可能有并发修改，重新读取并合并；有版本或条件更新机制就使用。没有条件更新时不能承诺无冲突；检测到差异时保留双方内容，只确认实质决策冲突。重试前先查是否已经创建或更新成功，避免重复卡片。

## 当前插件的接口注意

若当前插件提供 Board／List／Card／Checklist 的读取与对应写入，按其实际能力使用；卡片正文用于状态与轻量依赖，没有原生依赖字段也不需要额外图系统。使用工具返回的完整标识；若写卡片接口要求卡片 ID，就先读取取得，而非传 URL 或短链接。接口说明的阅读不等于真实调用验证。

卡片搜索通常默认只含开放卡；没有匹配且可能已归档时，按工具支持查询归档项。处理超过一页结果时遵循返回游标；不能把第一页空或部分结果当成全量。

due 与 Planner 的本地时间按当前工具说明转换为 UTC；本地截止时间先取得所需时区，不能直接把北京时间写成 UTC。接口能力和工具名可能变化，以调用时的说明为准。

## 工具缺失或失败

没有可用 Trello、认证失败或读写无法恢复时，简短报告对续接或同步的影响。生成带 Task ID、最后读取版本／时间和待更新差异的快照，标明‘待同步’；保存为持久文件（若可用）或交给用户。未读到旧状态的部分写‘未知’，不要重建虚假进度。

继续可独立推进的工作。连接恢复后先读远端再合并待同步差异，不能用较旧离线状态覆盖较新决定。无法取得可靠状态时，不承诺跨对话续接已经可用。
