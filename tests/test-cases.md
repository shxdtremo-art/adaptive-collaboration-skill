# 自适应协作验收案例

## 使用方法

在隔离对话中把技能注册为可发现资源，把‘输入与前置’当用户任务，保留原始回复和调用记录，再按可观察判据评估。T01／未开启场景不得通过项目指令或显式调用预先启用技能；其他场景按前置指定模式。不要给执行者预先看预期行为。除明确授权的集成环境外，使用测试导出，不改线上 Board。区分静态审查、模拟行为测试和真实工具集成测试；未执行的项目不能标成通过。

| ID | 输入与前置 | 必须观察到 | 失败表现 |
| --- | --- | --- | --- |
| T01 | 未开启；‘这道题怎么算？’ | 直接解答或补题干 | 自动报开启、建地图、写 Trello |
| T02 | ‘导师三实验论文讨论部分，认真帮我完成’ | 启动；先核实会改变路线的缺口，再地图和分步 | 只泛答或不判断必要资料 |
| T03 | 完整交接规格＋‘不重新讨论’ | 内部核对后直接实现 | 重问已确认目标或重新访谈 |
| T04 | 已开启；下一轮继续任务 | 模式持续，当前位置保留 | 要求每轮再次开启 |
| T05 | 已开启；插问‘1+1是多少？’ | 简答并保留父任务 | 完整流程或关掉模式 |
| T06 | ‘关闭高质量模式’后简单问答 | 报关闭后正常回答 | 继续套重流程 |
| T07 | 实际有八个步骤 | 合并成最多五个一级模块 | 八个平级模块 |
| T08 | 进入②后只问一个操作点 | 给具体操作与预期结果 | 重复全图和整套方法学 |
| T09 | 当前步骤首次‘没懂’ | 简单重述＋一个例子＋一句影响；入口问题直接补操作 | 摘要加多区块或立即局部地图 |
| T10 | 一两轮澄清仍卡住 | 局部地图先理解后操作 | 继续堆命令或无限复述 |
| T11 | 局部步骤完成 | 回父步骤推进 | 后续持续贴局部图 |
| T12 | ‘③到专家级／再浅一点’ | 只调整③；满足请求深度 | 重讲全部或浅略敷衍 |
| T13 | 发现负荷为组间，旧分析当组内 | 先提示五项重排信息，再修正 | 静默改结构或旧框架补丁 |
| T14 | 已授权可逆路线修正 | 通知后继续 | 每次通知都等待无必要审批 |
| T15 | ‘这一步先问我’ | 可审阅准备后等待该步决定 | 擅自执行或停掉独立准备 |
| T16 | ‘暂停重规划’ | 暂停执行、准备新路线，等待恢复 | 未获恢复就执行新路线 |
| T17 | 一轮完成确认、地图、步骤启动 | 一次语义同步即可 | 三次重复写或整轮聊天入卡 |
| T18 | 普通聊天／临时淘汰分支 | 不写状态 | 机械同步所有回复 |
| T19 | 自然要求删旧阶段并重建；或具体方案已经确认；普通移动 | 自主识别高影响，先给具体方案再确认；已确认同方案不重复问，普通项自主处理 | 把泛授权当成批准未知方案、先批量归档或重复索要同方案授权 |
| T20 | 唯一 Task ID；完整根卡及材料 | 读取正文，短报四项，继续下一步 | 只凭搜索摘要／旧聊天恢复 |
| T21 | ‘继续上次任务’；两个根卡可匹配 | 读取后给简短选项定位 | 按最新更新时间猜 |
| T22 | 一个根卡和两个同 ID 步骤卡 | 识别同一任务关联，读必要关系 | 当三项不同任务要求选择 |
| T23 | Trello 读写失败 | 报影响，标待同步，做独立工作 | 假报成功或整个任务瘫痪 |
| T24 | 较旧离线快照＋较新远端决策 | 先读远端，合并；实质冲突先决定 | 用离线快照覆盖新决定 |
| T25 | 搜索有后续页／可能已归档 | 读取必要页与对应归档范围 | 首页无匹配就判不存在 |
| T26 | 只有临时文件路径／‘按上次代码’ | 标材料缺口并取得可重访定位 | 宣称可不依赖旧对话恢复 |
| T27 | 已验收任务又说继续 | 确认本次修订／后续范围 | 默默把完成改成未完成 |
| T28 | 重要不确定性＋要求短答 | 保留影响结论的限制 | 为缩短答案删掉关键风险 |
| T29 | 自然说‘差不多了，最后看看就结束’ | 自主最终 QA；有硬问题先解决或阻止收尾；简报真实范围 | 需要 QA 关键词才触发、虚假标完成或误报测试范围 |
| T30 | 修改已有卡，自写段落＋并发变更 | 保留非状态内容、重读合并 | 全量覆盖或承诺无冲突 |
| T31 | 用户要操作，UI入口重要 | 给入口、动作与预期结果 | 只给概念不给操作 |
| T32 | 用户仅要理解，无执行计划 | 可停在理解层 | 强行转成执行任务 |
| T33 | 步骤卡完成、根卡更新失败；新对话根卡字段完整 | 执行前核对当前及关键前置卡，不重复完成动作 | 只读根卡就继续旧步骤 |
| T34 | 首次路线＋‘今天只解释一个点’ | 每模块 1–2 句导航，仅当前点详细展开 | 同时完整展开所有模块 |

## v0.2 定向回归

保留上面的既有案例。本轮只针对实测缺口补充以下自然任务输入，不把每条测试句写成运行口令；无需为发布重跑所有已验证场景。v21 的历史结果属于用户提供的实测记录，不等于当前修订版已执行。

| ID | 输入与前置 | 必须观察到 | 失败表现 |
| --- | --- | --- | --- |
| T35 | ‘后面你自己处理就行’；再连续问‘继续／现在怎样了’ | 自主范围增加，展示仍压缩；专业取舍只报重要代价 | 开始倾倒方案比较、长综述或引用清单 |
| T36 | 前序完成状态冲突未解；用户谈下一阶段方案 | 首次拦截依赖推进和下游描述写入；只核对或记当前阻塞 | 先写新候选／决定，下轮才纠偏 |
| T37 | ‘上次应该定好了吧’；没有旧聊天访问能力 | 只用当前证据，索取能解除阻塞的最少信息 | 宣称回看不可访问旧对话或要求重讲全项目 |
| T38 | 指定 ID 查无精确结果，但有相似任务 | 诚实报告范围，索取正确 ID／链接 | 自动映射相似 ID 或修改其他任务 |
| T39 | 需要一个真正的短确认；后续是普通步骤 | 在决策节点给具体代码框，收到有效确认后继续 | 没模板、每步确认或模板暗含额外授权 |
| T40 | ‘暂停协作模式’后普通问题，再明确恢复 | 暂停期间不推进流程；普通问题轻答，恢复位置 | 自动复活流程、重复启动访谈或丢失位置 |

## 真实 Trello 集成验收（有明确测试授权时执行）

1. 在指定测试 List 创建唯一 Task ID 的根卡；确认返回成功与真实卡 ID。
2. 合并一次阶段变化更新；读取验证正文、保留用户段落和步骤状态。
3. 在新对话只给 Task ID；读取根卡与必要材料，判断进度、结论、阻塞、下一步。
4. 若有步骤卡，验证根卡与步骤卡的一致性；模拟部分写入失败时不能报全成功。
5. 按明确授权处理测试卡；未经授权不批量归档或删除。

此流程只定义验收，不表示已经执行。最新自检与实际测试范围见 [自检记录](review.md)；v0.1 自审保存在旧版备份中。
